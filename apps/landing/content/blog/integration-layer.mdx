Here is what we built, why we built it, and the architectural decisions that make it deterministic.

### 1. Tenant Isolation – Not a Runtime Check

Before an event flows, we enforce a structural guarantee: **no tenant touches another tenant's data.**

`TenantId` is a newtype with a private field. No external construction. No raw UUID extraction. Every access is auditable.

This is not defensive programming. It is architectural law.

**PostgreSQL roles enforce physical boundaries:**

| Role | Schema | Purpose |
|------|--------|---------|
| `core_role` | `core` | Outbox, idempotency, shared infrastructure |
| `cinq_role` | `collab_crm` | CRM |
| `ops_role` | `collab_ops` | Operations |
| `vault_role` | `vault` | Inventory |
| `dial_role` | `dial` | Chat |
| `vista_role` | `vista` | Analytics |
| `dispatcher_role` | `core.outbox` | Relay (read/update only) |
| `admin_role` | All | DDL |

The dispatcher cannot insert events. CINQ cannot read DIAL tables. Physical enforcement.

---

### 2. A Unified Outbox with RLS

Every domain event – deal created, message sent, stock adjusted – flows through **one table**: `core.outbox`.

**Why one table?** Cross-domain events are the point. When CINQ wins a deal, VAULT reserves stock, DIAL creates a channel, VISTA updates revenue. One `LISTEN` channel observes the entire operating system.

**RLS enforces domain boundaries:**

```sql
CREATE POLICY outbox_cinq_insert ON core.outbox
  FOR INSERT TO cinq_role
  WITH CHECK (schema = 'collab_crm');
```

If DIAL tries to spoof a CRM event, PostgreSQL rejects it at the query planner.

**The dispatcher role:** It can read and update status, attempts, and locks. **It cannot alter payloads.** If the relay is compromised, it can retry or dead-letter a message. It cannot forge one.

**LISTEN/NOTIFY:** Dedicated `sqlx::PgPool` (size 3). Sub-millisecond delivery over the same TCP connection. No 5-minute polling.

Safety-net index:

```sql
CREATE INDEX idx_outbox_dispatch
  ON core.outbox (status, locked_until, id)
  WHERE status = 'pending';
```

If the listener misses a `NOTIFY`, periodic poll recovers in seconds.

### 3. Idempotency – 2⁻⁶⁴ Collision Risk

No outbox without idempotency.

**PostgreSQL advisory locks:**

```sql
SELECT pg_advisory_xact_lock($1::int4, $2::int4);
```

Transaction-scoped. Auto-releases on commit or rollback. No cleanup jobs. No lock table bloat.

Durable response storage:

```sql
CREATE TABLE core.idempotency_records (
  command_id UUID PRIMARY KEY,
  status TEXT NOT NULL,
  response_status SMALLINT,
  response_body JSONB,
  response_headers JSONB DEFAULT '{}',
  aggregate_id UUID,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  completed_at TIMESTAMPTZ
);
```

**Flow:** Retry blocks on the lock. Completed request serves cached response. No double-charges. No duplicate deals.

Collision probability: **2⁻⁶⁴**. Negligible. Not zero. Acceptable.

### 4. Domain Layer – Pure Functions

Domain crates contain **business logic only.**

No I/O. No HTTP. No database connections. No system clock. No random number generation.

**Inject capabilities:**

```rust
pub trait IdGenerator: Send + Sync {
    fn new_uuid_v7(&self) -> Uuid;
}

pub trait Clock: Send + Sync {
    fn now(&self) -> SystemTime;
}
```

Production: UUIDv7 and `SystemTime`. Tests: deterministic mocks.

**Domain logic is testable without a database. Deterministic. Pure.**

---

### 5. Error Taxonomy – No `unwrap()`

**`DomainError`** – business rule violations. No I/O details leak.

- `Validation`, `NotFound`, `Conflict`, `BusinessRule`, `TenantViolation`, `Unauthorized`, `Forbidden`

**`RepositoryError`** – infrastructure failures. Mapped from database constraints without coupling to `sqlx`.

- `UniqueViolation`, `ForeignKeyViolation`, `CheckViolation`, `NotFound`, `Database`, `Connection`, `Unknown`

**No `unwrap()` in domain code. No `expect()` in domain code.**

Every failure is typed. Propagates cleanly to the API.

---

### 6. JSONB Custom Fields – 3-Tier Strategy

No EAV tables. PostgreSQL `JSONB` with graceful degradation:

| Tier | Operator | Performance | Use Case |
|------|----------|-------------|----------|
| 1 | `@>` | Indexed, <10ms | Exact match |
| 2 | `->>` ILIKE | Scan, <100ms | Single-field text |
| 3 | `jsonb_each_text` | Expensive, rate-limited | Cross-field search |

High-traffic fields get promoted to columns. No schema migrations for every new field.

### 7. What We Excluded

This architecture is defined as much by what we excluded as what we included:

- No microservices. One Rust binary.
- No Kafka. No RabbitMQ. PostgreSQL `LISTEN/NOTIFY` is sufficient.
- **No per-user pricing. $15 (1 app), $39 (5 apps), $79 (10 apps). Fixed.**
- No AI bloat. No LLM calls in the event pipeline.
- No `Serialize` on PII newtypes. `Debug`/`Display` redact. JSON serialization isolated to API wrapper structs.
